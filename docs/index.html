Features

What this repository contains.

This is an experimental fork. Feature availability may depend on the device, permissions, model/provider setup, and current branch.

AI chat and tools

The Android app includes AI conversation, provider integrations, and tool invocation. Available tools and actions depend on the current branch, assistant settings, device permissions, and configured services.

In-app browser

The repository includes an in-app browser as part of its Android app. Its available interactions depend on the current implementation and configuration; see the source and root README for the supported scope.

Web search

Web search is one of the repository's documented app capabilities. Which search providers or actions are available depends on the current build and configuration.

Workspace and app services

The repository contains workspace and application-internal web-service modules. Their availability and behavior depend on the current build and configuration; consult the source for what this branch exposes.

Find & manage files

Workspace tools can list, read, write, and edit files in a bound workspace. Local file-management tools can operate on permitted files; available paths and actions depend on the active workspace and granted permissions.

Music + media

Audio playback uses an Android MediaSession and foreground service, exposing standard media controls to system surfaces and compatible devices. Queue behavior is limited by the current implementation.

Skills

The repository includes a Skills system for adding assistant capabilities. Supported formats and available skills depend on the current build; see the root README and source for the implemented scope.

MCP servers

The app includes Model Context Protocol integration. Available servers, tools, and permission behavior depend on the current configuration and branch.

Doctor

A built-in health checkup: a top-to-bottom audit of permissions, background services, database integrity, network, and diagnostics. Per-row auto-fix grants the missing permission, restarts the service, or rebuilds the search index.

External triggers

When enabled in assistant settings, other apps can send RUN_TASK intents through the External Automation Intent API. The assistant can restrict trusted caller packages and show a recent invocation log.

Safety in three layers

Per-assistant toggles: every tool starts off; flip on only what you want. Per-call approval: tools that change something ask first, with Allow once, this chat, always, or Deny; permanent grants are listed under Settings and revocable any time. HARDLINE floor: wipe-everything commands, fork bombs, system file destruction, and shell tricks to bypass the rule are blocked unconditionally, even if you ask for them. Passwords and API keys never hit log files, cloud backups skip saved credentials, and web fetches that resolve to a private network address are refused, so the assistant cannot be talked into probing your LAN.

Models

Bring any model. Or none at all.

Paste an API key, sign in with an account you already pay for, or download a model and run it entirely on the phone.

Cloud APIs

OpenAI, Anthropic, Google, DeepSeek, xAI, Ollama, and any OpenAI-compatible endpoint. OpenRouter gets first-class support: auto-detected model capabilities and pricing, plus a fallback model list tried in order when your primary is down, rate-limited, or refuses. Providers that discount cached tokens show cache hits and misses under each reply.

Sign in with an account

Codex: your ChatGPT plan over OAuth. Grok: SuperGrok or X Premium+ over OAuth. Google sign-in: Gemini through Google Cloud Code Assist with no API key; several accounts round-robin, each showing its remaining daily and weekly quota.

Fair warning: the Google sign-in reaches Google's services through a client Google did not approve, and Google's terms allow accounts to be suspended or terminated for that. The app shows this warning prominently before you enable it. Use a throwaway account, never one tied to your email, photos, or work.

Fully on-device

Download a local model (Gemma, Qwen, and more) from HuggingFace search or from storage and run it through llama.cpp (GGUF) or LiteRT, with GPU acceleration where supported. No key, no network, nothing leaves the phone. Pixel 8/9/10 users can also enable Gemini Nano via AICore (currently requires the AICore Beta).

Quick start

Build from the current source.

This repository does not promise a stable or official APK. Follow the root README and inspect the current build configuration.

1

Read the README. Clone this repository and use its Gradle Wrapper instructions to build a Debug APK. Do not treat a locally built Release APK as an official signed release.

2

Add a model. Settings → Providers → pick one → paste an API key. Or sign in with a ChatGPT, xAI, or Google account, or download a local model and skip the network entirely.

3

Turn on what you want. Settings → Assistants → tap your assistant → Local Tools → flip the categories you want enabled.

4

Check the current build. Feature availability can differ from other forks and upstream releases; use the root README and checked-in source as the reference.

5

Start a chat. Tools you have not enabled are unavailable; other behavior follows the current build and assistant settings.

FAQ

Common questions

For questions about this repository, see its README and issue tracker.

Does this require root?
The root README does not list root access as a build or runtime prerequisite. Permission needs and available features depend on the current build, device, and enabled integrations; use the README and in-app permission prompts as the source of truth.
Is my data sent anywhere?
Network use depends on the model/provider and services configured by the user. The repository includes local-model integrations, but users should check the active provider, app permissions, and backup settings for the behavior of their build.
What LLM providers work?
Cloud APIs: OpenAI, Anthropic, Google, DeepSeek, OpenRouter (first-class, with fallback models), xAI, Ollama, and any OpenAI-compatible endpoint (Groq, Mistral, vLLM, LM Studio, etc.). Account sign-ins: Codex (ChatGPT plan), Grok (SuperGrok or X Premium+), and a Google account sign-in for Gemini. On-device: downloaded GGUF/LiteRT models, or Gemini Nano via AICore on Pixel 8/9/10+.
What is the Google account sign-in, and is it risky?
It signs in with a Google account and generates through Google Cloud Code Assist, so you get Gemini without an API key, with several accounts used round-robin and per-account quota bars. It is risky: the requests reach Google through a client Google did not approve, and Google's terms allow them to suspend or terminate accounts for that, with no appeal path built for this case. The app shows this warning prominently before you can enable the provider. If you use it, use a throwaway account you can afford to lose.
How are dangerous tools handled?
Three layers, strictest last. (1) Every tool category starts off; you flip on only what you want, per assistant. (2) Some consequential tools may require approval before running; the available actions and approval options depend on the current implementation and settings. (3) A short HARDLINE list (wipe everything, reboot, fork bombs, system file destruction, and shell tricks to bypass the rule) is blocked unconditionally. Even if you tell the AI to do one of these, it won't.
How is this different from vanilla RikkaHub?
This repository is a personal experimental fork based on RikkaHub. Its checked-in code includes AI chat, provider integrations, local-model support, agent tools, Skills/plugins/MCP, an in-app browser and workspace-related modules, search, speech, and document processing. Features may be incomplete or differ from other forks; see the root README and current source.
Is this affiliated with the upstream RikkaHub team?
No. The root README describes this as an independent derivative and links to the upstream project and other source repositories. It is not an official RikkaHub release.
Does this repository provide an official APK?
No. This repository does not promise formal release support. The root README documents building a Debug APK; it also notes that the Release variant uses a debug signing configuration and is only a temporary local artifact, not a formal distribution build.
What languages does the interface ship in?
English, Simplified Chinese, Traditional Chinese, Japanese, Korean, Russian, and Arabic. The app follows your system language and falls back to English. Right-to-left languages render correctly in chat, and code blocks stay left-to-right.
